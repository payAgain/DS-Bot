# 统一审批入口布局修正

用户要求同一原始请求在主 Bot 只保留一个有效操作入口，普通工具过程不展开，等待用户不能显示成持续执行。范围仅 DS Bot 客户端及测试，不修改审批端点、权限范围、电脑系统权限或 host。

## 核查证据

生产包为 0.3.2-payagain.6；已将 102 个 host/shared/client 交付文件与 .6 固化包逐个比较，完全一致。直接使用已有浏览器登录读取当前公开状态时，截图里的应用请求已经结算：appAsks=[]、approvals=[]，页面仅剩旧 Cua 历史行和空审批横条。因此无法从截图还原当时两个区域的原始 ID，不能据外观断言存在两份同 ID 的交互。

源码确认：inbox 先按待处理数生成外壳与来源标题，却允许 Chief 自己的卡继续留在聊天中；子 Dock 随后因 drawn 状态不渲染。单个请求即可形成“聊天操作卡 + 空汇总壳”。此外 AppAccessDock 原来只 find 第一个请求，不能完整展示同 Bot 的多个原始请求。

## 行为

- 所有待处理请求在 Chief 统一区交互。源聊天只保留短状态与跳转；聊天内对应的 live 请求不再画第二组操作按钮。已结算问题/回复历史继续只读展示，不将历史工具重新当待审批。
- 唯一性按原始 request id，仅同类型的重复 ID 去重，绝不按 appName、来源名或文案合并不同请求。
- 应用访问 Dock 展示同 Bot 的全部原始请求，保持 ask.id、ask.sessionId、callId 与 computerAppAnswer 的 deny/once/always 原值。文案明确 once 是发起请求的对话段，always 是此 Bot 的所有对话。
- 空队列不留空标题、来源占位或常驻“无待处理”条。紧凑标题显示待处理数，来源用小字号，长队列在限制高度内滚动，保留输入区。
- 普通 cua 步骤不再绘制原始名称、工具行或截图缩略图；应用授权与必要交接仍可处理，电脑详情页功能保留。
- 有阻塞请求时显示静态“等待你处理”，不显示执行计时或执行闪动；恢复执行后计时从恢复时重新开始，表示当前执行阶段，不把用户等待加进去。后台学习建议不把正常工作误标成等待。
- 失败答复可重试，重复点击仍只调用一次原端点。任何授权仍由原 host 校验，无新的自动批准逻辑。

## 验证与发布

单测覆盖单 ID 唯一交互、同 Bot 多 ID、跨 Bot、同名应用不合并、过期/取消/结算、原 ID 与范围、重复点击和失败重试、历史不复活、等待状态与恢复计时。使用真实 React 产品组件和明确合成数据进行宽屏/390px窄屏浏览器检查，再在同一生产服务刷新验证。测试不发真实权限请求或点击真实授权。

本轮只替换经过构建验证的客户端交付文件，并保留生产原文件备份。host 代码不变，不重载 host 或重启 DSH/Magpie。固化 .7 包供后续统一版本安装；前端更新与当前 host 版本分别报告。
