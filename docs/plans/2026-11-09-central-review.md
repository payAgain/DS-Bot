# 主 Bot 统一审批与技能复用

用户明确要求由用户在主 Bot 对话统一处理各 Bot 请求，取代逐个对话确认。主 Bot 只承载界面，不代表用户签字，不授予模型自动批准能力。

## 本次实况

model-gateway-maintenance 与 macos-gateway-maintenance 是两个不同名称、不同全文、不同提案 ID 的技能，生成时间相隔约26秒，都早于第一张被批准。目前两张已分别被用户批准，不是尚未清理的同一审批 ID。保留两份批准审计，不将语义相似当成逐字相同，也不擅自合并新增条款。

## 实施

- 从现有团队状态、work.approvals、浏览器/电脑交接状态汇总请求，在第一主 Bot 当前对话的审批入口复用原卡片。
- 展示来源 Bot、原请求 ID、操作与权限范围；保持原 sessionId、requestId 与原答复端点。一次性执行仅发送 allowed-once/rejected，不生成新的请求、不跨动作复用批准。
- 工具/沙箱审批使用已有公共 approval/request 及 answerApproval；技能、问题、show_view、密钥、连接器和邮件确认复用插件已有状态和端点；浏览器/电脑交接复用原卡片。
- 原 Bot 的等待与审计保留。用户在主 Bot 处理后原卡随同一状态关闭，无需第二次批准；原位置若保留镜像，也不能产生第二份请求。
- 密钥继续使用安全卡片，不读取已有密钥值，不要求在普通消息中输入。
- 未纳入公开团队状态的 DSH 原生阻塞提问、非 Bot Session、操作系统权限弹窗、外部 OAuth 同意仍有宿主/操作系统边界，不能承诺都搬进主 Bot。

## 技能去重

- 只复用已批准且当前目录仍具有相同描述与全文的版本；使用内容指纹，不按名字或相似度授予新内容。
- 待批同版本提案由一次用户批准统一结算，保留各来源的审计与关联。并发批准序列化，重复点击不重复落盘或改变权限。
- 新全文、修改条款、已批准后又被编辑的内容仍需新的批准。生成器提供已批准技能全文及待批目录以减少不同命名的重复提案；语义去重仅作为审阅提示。
- 已批准学习技能共享给团队，确保当前与新增 Bot 的目录可用；通过插件能力接口刷新，不修改 DSH 运行时。

## 验证与部署

隔离测试同内容跨 Bot、并发/重复点击、新内容保留待批、取消/过期、同 ID 在主 Bot 处理后源请求恢复。运行 build、单元、lint 和 host smoke。前端可热替换；host 逻辑需协调安全重载，不能在任务运行时未经协调重启。保留旧发布包，不把磁盘更新等同于当前进程已执行新 host 代码。
