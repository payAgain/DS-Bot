# 连接器界面统一

用户明确要求把 Composio 从原生连接器列表中独立成模块，避免推荐行、巨大账号权限表单和应用目录交错。

- 原生连接器主页面保留一致的紧凑网格，增加一个同规格的「应用连接 / Composio」模块入口，不在主目录内挂载扩展账号表单或目录。
- 独立子页管理 Composio 应用目录、已连接账号和原授权等待状态；服务配置再进入该模块的设置页。总连接数仍包含原生与扩展账号，但汇总页仅给出紧凑模块入口，不混入权限表单。
- 账号默认仅显示应用图标、名称、连接与授权摘要和管理按钮。用户打开管理后才显示启用开关、Bot 勾选、内部 ID、重新连接及断开。保存和断开继续使用原端点与确认流程。
- 同名 composio toolkit 不删除，明确标成「Composio API 工具」，说明它是可启用工具集，区别于平台模块及服务配置。
- 保持主题变量、原网格图标和按钮尺寸；窄屏折为单列，按钮和标题不挤出容器。
- 不改变 Gmail/QQ 授权、Bot 权限、后端执行或 OAuth 安全边界；视觉检查只导航和展开管理，不生成新授权。

验收：构建一致性、单元和 lint；以 browser-skill 在现有 GUI 实际检查宽屏、窄屏、当前主题和深色，保留截图并复核授权基线。仅更新前端，无须重载 host。
