# 交接在插件重载后的恢复

生产实证：两个历史通知作为 message_bot 默认 request 进入了不同 Chief 根任务。接收方在已有回合中读到通知；该回合跨越插件停启，随后正常 completed，但没有为通知重排独立回合，也没有 replyTo。树的 parent 无环；按 Bot 聚合后出现互等。实际业务均已结束，不能把通知误记为待执行工作。

本修复从已验收 .10 出发，不混入待合并的上游 dev。插件重新加载时用公开 agents 与 sessionController.inspect 读取仍在运行的回合，恢复原触发、joined/later 与文本；检查期间收到的事件按持久序号衔接，避免旧任务的答案回给新请求。完成/失败/停止仍走原路由；已结算请求保留身份，重复终结不重复外发。单一任务的 A→B→A 继续被祖先判定拒绝，不用 Bot 聚合互等替代任务级判断。

新增显式 reply_to=none 单向通知：仍投递给接收方，但不创建 work、不期待回交；不根据正文猜测消息是否通知。原默认请求行为保持。群聊不接受该参数，以免把通知变成隐式群任务。

新增受支持的 resolve-handoff 维护端点：只接受精确 work ID、预期 parent 和审计说明；只释放无下游的历史通知，拒绝运行中/未读请求。保留审计记录与父任务结果，并向父任务交回明确的行政结算说明；不宣称原任务执行成功，不停止会话、不清空其他等待。重复调用返回已结算，不重复投递。生产仅针对两个已经双方与 Chief 确认无业务依赖的通知调用，不按年龄批量清理。用户暂停其他 Bot 时，显式使用 `notify:false`：保留父任务行政结算结果及审计，但不唤醒任何 Bot、不触发模型回复；不将行政结算称为业务执行成功。

SSE 错误：持久诊断为 OpenAI 客户端对 SSE data 做 JSON.parse 时失败，未留原始失败响应，不能进一步断定 Magpie 或远端产生坏帧。本轮模型已恢复正常，先核对 Git 现状再继续一次，不补丁宿主解析器、不无限重试。

验证涵盖重载中的原始请求与新增请求、A→B→A、结果回交后 idle、失败/取消/跨 part、真实等待保留、通知不建等待、审计释放与终结幂等。源码/测试、激活与生产端点状态分别记录；不把 mock 当自然模型行为保证。
