# 个人版连接器与手机接口

本轮开发日期：2026-11-08。源码版本：`0.3.2-payagain.1`。
用户要求先完成开发，完整自动测试、浏览器验收、真实账号联调和手机
验收后置。本版本不引用旧 Tailscale 版本的测试记录作为新增功能的证明。

## 连接器入口

设置 → 连接器 → **更多应用**，打开个人 Connected Apps 页面。

1. 在 Composio 创建自己的项目，填写项目 API key。
2. `Composio 用户标识` 留空会创建独立标识；已有项目账号需要填写当初
   使用的相同标识，才能读取对应账号。
3. 搜索应用，点击连接并在浏览器完成授权。需要自己的 OAuth 或 API-key
   配置时，可提供该应用在项目中的 auth config ID。
4. 在已连接账号中选择允许使用的 Bot，以及“只读”或“修改前请求批准”。
   新账号默认不授权给任何 Bot，修改权限需要保存。
5. 可刷新账号、重新连接失效账号，或确认断开。多账号使用明确的账号 ID，
   不把一个供应商的所有账号自动授予全部 Bot。

无需登录的应用可以显式启用，然后同样按 Bot 分配权限。
原有 MCP、邮箱及原生连接器继续使用原入口。

重新连接成功后，原账号权限迁到替代账号，旧账号的本地 Bot 权限关闭。
替换 Composio 项目会清空本地账号授权；移除项目 key 不等于撤销服务商
上的所有 OAuth 授权。来自 OpenMausBot 托管服务的授权不会被自动复制。

## Bot 工具

- `connected_apps`：查看该 Bot 有权使用的账号。
- `search_app_tools`：按账号搜索操作，返回具体工具版本和输入结构。
- `execute_app_tool`：校验账号归属、所属应用及当前权限后执行。

写操作及未明确标为只读的操作需要 DSH 单次审批。审批显示具体操作和参数；
审批过程中变更权限、断开账号或停止当前工作会撤销未执行的请求。
未知结果不自动重试。SDK 禁用自动读取本机文件上传，外部接口不会因一个
参数看起来像路径而自动取得本机文件。

项目 key 保存在 DS Bot secret store，scope 为空，不进入 Bot shell。
接口只返回账号元数据，SDK 的账号认证字段不进入页面或模型。动态目录与
OAuth 使用 Composio 服务，需要自己的项目可用且应用授权有效。

## 手机配套

手机源码仓库：`payAgain/ds-bot-mobile-app`。
匹配本轮电脑端 App 插件：`ds-bot-mobile-app@0.3.2-payagain.1`。
目标运行时是 DSH `0.2.2-rc.1`，不修改 DSH 安装文件。

本插件新增 `mobile-describe`、`mobile-submit`、`mobile-receipt` 产品接口。
手机发送保留设备请求身份，准备该 Bot 的连接能力，再进入原生 Session；
回执保留于产品请求库。接口校验当前会话和群成员，不能把旧请求转投另一个
会话，也不能把未知提交结果当作未执行。

对应手机插件实现配对后的聊天、历史、单聊增量回复、审批/提问、停止、
重连、图片与文件上传，以及按消息归属下载附件。配对与网络配置仍在手机
插件中管理，Composio 项目 key 不对手机开放。

## 构建与后续验收

在 `ds-bot/` 执行 `npm ci`、`npm run build`。生成的 `client.js` 随源码提交。
根目录可执行 `npm pack ./ds-bot --ignore-scripts --pack-destination artifacts`
生成开发包。

本轮只进行源码语法、类型及构建检查，不修改日常运行的 DSH profile。
发现此前 `file:` 目录安装与源码共享硬链接后，已将安装副本的文件独立恢复
到原 `0.3.1`，开发源码保持本版本。后续部署使用打包的 `.tgz`，不再依赖
目录硬链接。当前 profile 中原目录依赖仍需在正式升级时由插件管理器换成
归档依赖，避免其他包管理操作重新导入开发目录。
真实 OAuth、服务商写操作、账号撤销、手机签名安装、Tailscale 跨网络、
并发审批和断网恢复需要后续隔离验收。不能把“已写入代码”视为这些检查通过。
